### Improved

- When Chat can't answer, it now tells you. The status reflects whether Chat can reply right now, a failed reply shows the reason, and if your model key was refused it points you to Settings → Model keys. Failed replies also stay in the conversation after you reload, under the message they answer.
- When a workflow's AI step uses a model key the provider refuses, the step now fails right away. The run says the key was rejected and points you to where model keys are set. Before, the step retried several times and then reported a problem with the model's output.

### Fixed

- The chat beside a document now connects and answers. Before, it stayed on "reconnecting" and every message failed.
- People now appear by name. This covers document version history, chat messages and avatars, which used to show raw identifiers. In Settings, Muted subjects now lists muted cases by their titles.
- A new organization can now create its first entity type in Entities. If a request is refused, the page shows the explanation rather than a bare error code.
- The ⌘K menu now reaches every place in the navigation, including Chat, Notifications and the Knowledge base.
- In Cases, "Start one" on a case type with no workflow is now disabled, with the reason shown beside it. Before, pressing it did nothing.
- The Intake page in Cases no longer offers a webhook address where webhooks aren't available. It says "Not available here" instead.
